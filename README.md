# OC 角色卡存檔區 — OC Card Archive

> 改這個專案之前請先看 [`NOTES.md`](NOTES.md)：那裡寫了踩過的坑、不能退回去的規則，以及還沒做完的事。

把 OC 的人物設定做成一張一張的卡片收好。左邊是作品（分組），右邊是卡片牆，點開一張卡就是完整的角色設定——資料列、長文段落、標籤、頭像。

姊妹專案：[`evonne93327-create/world_2`](https://github.com/evonne93327-create/world_2)（世界觀架構工作台）。
這個存檔區的卡片**可以直接匯出成那邊看得懂的角色文檔**，作法見下面〈[跟世界觀架構工作台一起用](#跟世界觀架構工作台一起用)〉。

---

## 功能

**卡片**
- 三層結構：**資料列**（性別、年齡…短短一行）、**設定段落**（外觀、性格、背景…大段文字）、**標籤**
- 欄位名稱與段落標題都可以自己改、自己增刪、自己調順序——每個人記角色的方式不一樣
- 頭像可以上傳圖片（自動縮圖）或選一個 emoji
- 七種分類顏色，名稱可以改成你自己的分類方式（主角群／反派／設定中…）
- **完成度**：告訴你這張卡還有幾格空著，分母只算卡片上真的存在的格子

**整理**
- 多個作品（分組），卡片可以搬來搬去
- 搜尋會打到**所有**內容，包括段落內文——角色一多，你記得的往往是某個細節而不是名字
- 依標籤、分類顏色、我的最愛篩選；依最近修改／建立時間／名稱／顏色排序
- 批次模式：一次選多張，一起刪或一起匯出
- 垃圾桶（保留 60 天，可還原）

**匯出與匯入**
- 匯出：JSON（卡片）、**JSON（給世界觀架構工作台）**、HTML 卡片頁（可列印、給別人看）、純文字 TXT、整包 JSON 備份
- 匯入：本工具的完整備份、卡片陣列、**世界觀架構工作台匯出的文檔陣列**（會被拆回角色卡）

**可安裝、可離線**
- 是一個 PWA，可以裝到手機主畫面或電腦上，開起來沒有瀏覽器網址列
- 離線也能開啟與編輯；資料本來就存在本機，網路只負責抓靜態檔案
- 日間／夜間／跟隨系統

## 本機執行

沒有安裝步驟，也沒有打包流程。用任何靜態伺服器把資料夾開起來即可：

```bash
python3 -m http.server 8000
# 然後打開 http://localhost:8000
```

> 直接用 `file://` 開 `index.html` 也能顯示，但離線安裝需要正常的網域來源（https 或 localhost）才能運作。

## 測試

```bash
node --test
```

不需要 `npm install`，也不需要瀏覽器——專案刻意維持零依賴，測試也跟著這個取捨走。`tests/helpers/load-app.js` 用 Node 內建的 `node:vm` 把瀏覽器端的 js 載進沙箱，補上幾個 DOM 空殼，就能直接拿裡面的純函式來測。

測的是三類東西：

- **純函式**（`tests/pure.test.js`）：標籤正規化、搜尋比對、完成度計算、排序、HTML 跳脫、圖片來源白名單。
- **跟世界觀架構工作台的格式約定**（`tests/bridge.test.js`）：匯出的文檔形狀、段落標題與 hashtag 的寫法、卡片→文檔→卡片的往返，以及匯入時對畸形資料的防禦。這組測試是拿來釘住兩邊約定的——誰改了輸出形狀，那邊的匯入就會默默失效，這裡會先紅。
- **離線清單的一致性**（`tests/shell-manifest.test.js`）：`sw.js` 的 `SHELL` 跟 `index.html` 實際載入的檔案必須對得上，順便檢查 `<script>` 的載入順序。這兩份清單是手動維護的，加了新檔案卻忘記補進去的話，離線時會無聲少一塊功能。

## 跟世界觀架構工作台一起用

兩個 app 各做各的事：這裡管「一個角色的設定長什麼樣」，那邊管「角色之間、跟世界之間的關係」。所以不是把一邊塞進另一邊，而是**讓卡片走得過去**。

### 現在就能用：把卡片送到那邊

1. 在這裡點 **📤 匯出** → 選好要匯出的範圍
2. 選 **「JSON（給世界觀架構工作台）」**
3. 到世界觀架構工作台 → **設定 → 匯入** → 挑那個檔案
4. 每張卡片會變成一篇角色文檔，落在你當時選的世界觀底下

轉過去的內文會用那邊的既有寫法：段落標題寫成 `# 外觀`（會被抽成章節快速跳轉），標籤寫成 `#主角群`（會被抽成 hashtag 並套色）。所以送過去之後，那邊的篩選、跳轉、白板投射全部都能直接用——把角色拉到白板上連關係線，不需要任何額外步驟。

反過來也通：那邊匯出的 JSON 丟進這裡的 **匯入**，會被拆回角色卡（`# 基本資料` 那一段會還原成資料列）。

> 兩邊的資料各自獨立，不會自動同步。送過去的是複本，改了這裡不會動到那邊。

### 如果之後想真的合併成同一個 app

這個專案的變數命名、CSS token、存檔慣例都是照著 world_2 寫的，就是為了留這條路。合併的具體步驟寫在 [`NOTES.md`](NOTES.md) 的〈如果要併進 world_2〉那一節。

## 專案結構

純 vanilla JavaScript，零依賴、無打包步驟。所有檔案用 `<script>` 依序載入，共用全域作用域。

```
index.html          版面與所有彈出視窗的 markup
ui-tokens.css       設計 token（顏色、間距、字級、圓角、層級）
style.css           版面與元件樣式
manifest.json       PWA 設定（名稱、圖示、啟動方式）
sw.js               Service worker：離線支援
icons/              app 圖示

js/
  state.js          預設資料、常數（顏色、上限值）、全域狀態變數、safeStorage*
  main.js           純函式（搜尋、排序、完成度、標籤…）＋ 版面切換與作品側欄
  storage.js        localStorage 讀寫、形狀補齊、垃圾桶清理；saveData() 是所有資料異動的唯一出口
  cards.js          卡片牆、篩選列、卡片詳情、批次模式
  editor.js         角色卡編輯面板、自動存檔、頭像縮圖
  modal.js          圖示選擇器、作品設定、分類設定、垃圾桶、更新提示
  import-export.js  匯出與匯入，以及跟世界觀架構工作台的格式互轉
  theme.js          日間／夜間模式、設定總表
  app.js            啟動進入點、service worker 註冊
```

## 三個值得知道的設計決定

### 編輯是即時寫入，不是「改完按儲存」

試過草稿複本的作法（改完按儲存才寫回去），但這個 app 的使用情境是一邊想一邊打，手機上切出去接個電話回來草稿就沒了；而且「忘記按儲存」是最容易發生、後果最嚴重的一件事。

改成打完停手 600ms 自動寫入之後，離開時不需要問「要不要儲存」，誤刪則由垃圾桶兜底（60 天）。代價是「反悔」要靠垃圾桶而不是「取消」，這個交換在這種長期累積的資料上是划算的。

### 頭像一律縮到 320px 再存

localStorage 大約只有 5MB，而圖片是整張 base64 存進去的。原圖直接存的話，一張手機拍的照片就是 3～5MB，第一張就把空間吃光，而且使用者完全沒有感覺。

縮到 320px 邊長、JPEG 0.82，一張大約 20～40KB，一百張角色卡也還在安全範圍內。頭像在畫面上最大也才 96px，肉眼看不出差別。萬一還是滿了，`saveData()` 會擋下來並跳出提示要你立刻備份——不能讓「存不進去」這件事靜悄悄地發生。

### Service worker：網路優先，不是快取優先

一般 PWA 教學都是快取優先（先給快取、背景再更新），但這個 app 是持續部署的，快取優先會讓人被鎖在舊版程式碼裡——而且很難自救，因為連強制重新整理都是由 service worker 回應，根本沒碰到網路。

所以這裡刻意反過來：**先走網路，失敗才回退快取**。連線正常時不會變快，但「更新一定拿得到」。對這個 app 來說這個取捨很划算，因為資料本來就在 localStorage，網路只負責抓靜態檔案。
